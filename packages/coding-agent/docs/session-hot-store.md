# Pi hot session store (isolated prototype)

The logical Pi session ID and authoritative append-only `<session>.jsonl` path do not change. Neither the live Worker7 session nor its old transcript is migrated by this change. This implementation is separate from the stopped-worker/replacement prototype in `session-checkpoint-prototype.md`; it does **not** require BotMux worker rotation.

When the source exceeds 10 MiB and the current branch has a valid compaction, Pi atomically writes a private `<session>.jsonl.hot` snapshot. It holds a minimal, reparented branch with the original compaction, retained entries and suffix, plus model/thinking/title state, cumulative cold usage/count, source inode/offset and a SHA-256 boundary anchor. The old JSONL is left byte-for-byte intact at that moment. At restart Pi validates the snapshot and parses only the active suffix after its byte offset. Missing/stale/corrupt snapshots fall back to the normal full JSONL load; **a sidecar is never authoritative**. The cache is at most 32 MiB; when active content cannot fit, no data is discarded and a full load is used instead.

The original JSONL remains the cold history **and** the append target (there is no physical archive move). `getArchivedEntriesPage(cursor, limit)` reads forward, at most 200 historical entries per call, without hydrating the entire history; explicit full-history/tree/export operations may still load it all. Normal model projection, startup rendering, footer totals and compaction bookkeeping use the hot branch. User-visible image entries persist a `pi-blob://sha256/<hash>` reference plus byte length and available pixel dimensions in private `<session>.jsonl.images/`; hot restart keeps refs. Rendering selected entries or preparing a provider request validates and reads only those blobs. Missing/corrupt active images fail closed.

With compaction enabled, >16 MiB of active on-disk data triggers compaction independently of model-token pressure before the next assistant response. This is a **soft trigger**, not a strict disk quota: compaction may be disabled, fail, or leave an oversized retained message, and the original append-only history continues to grow. No unsafe truncation occurs. A source edited in place outside the header and boundary anchor is outside the append-only assumption; the sidecar is not a cryptographic integrity proof of the complete prefix. Atomic rename gives process-crash visibility, **not power-loss durability**. No production deployment, BotMux daemon integration, or full-suite green claim follows from this prototype.

Isolated verification: `npx vitest run test/session-hot-store.test.ts test/session-image-store.test.ts test/session-checkpoint.test.ts test/session-manager test/compaction test/footer.test.ts`; `npm run build:unbundled`.
